# Backend architecture

Modular monolith (Spring Modulith): one top-level package under `com.template` per **bounded context** (BC), plus technical modules. Each BC is hexagonal, with its domain split by aggregate. See ADR 0003.

```
com/template/
  Application.kt        @SpringBootApplication only (no manual component scan)
  shared/               technical module: ErrorResponse, DatabaseConfig, JacksonConfig, OpenApiConfig, UserId
  auth/                 technical module (not a BC): config/, keycloak/, web/
  <bounded-context>/    e.g. example/
    domain/<aggregate>/
      model/            data and value types: data class, value class (checked factories), enum, sealed
      logic/            pure functions on the model (rules, calculations, parsing)
      port/             interfaces to the outside (repositories)
    application/        use cases (@Service); depend on domain only; return sealed results, not exceptions
    adapters/
      web/              controller, scoped exception handler, request/response DTOs, mapper
      persistence/      Exposed tables, records, record mapper, repository implementation
```

## Dependency rules (enforced by `ModularityTest` and `HexagonalArchitectureTest`)

- Modules: no cycle, and a module only uses another module's base package (its public API). Sub-packages are internal. Talk to another module through its public API or an application event (`ApplicationEventPublisher` + `@ApplicationModuleListener`); never read its tables.
- `auth` and `shared` are technical modules: no domain, no ports. `shared` is used by every BC; keep it tiny.
- `domain` is pure Kotlin: no Spring, Exposed or Jackson, and no dependency on `application` or `adapters`.
- `model` depends on neither `logic` nor `port`; `logic` does not depend on `port` (only `application` calls ports).
- `application` does not depend on `adapters`.
- `adapters.web` and `adapters.persistence` do not depend on each other. Each has its own shapes (DTOs, records), primitives only (enums as `String`), and a mapper to and from the domain.
- Exception handlers are scoped to their module: `@RestControllerAdvice(assignableTypes = [...])`. No global handler with a catch-all (it turns Spring MVC errors into 500s).

## Domain conventions

- Anemic aggregates, functional style: data in `model/`, behaviour as pure top-level functions in `logic/`.
- Value objects: `@JvmInline value class` instead of primitives (e.g. `Amount`, `ItemName`, `shared/UserId` for the Keycloak `sub`). Never a `typealias`: it is not a distinct type. A value object with invariants has a private constructor, built by a checked factory returning a sealed `Parsed<T>` (`Ok(value) | Refused(code)`, single-value rules: required, bounds, length) or by `reconstituer` (trusted, persistence adapter only, enforced by `HexagonalArchitectureTest`). No check in `init`. Computed values that may leave the bounds of an entered one (sums, negative differences) get their own unbounded value class, never a raw primitive.
- Parse, don't validate: the web mapper reads the request into a nullable draft (`<Aggregate>Draft`), or an unreadable result for an unknown enum value; a pure domain function `parse<Aggregate>(draft)` in `logic/` returns `Valid(aggregate)` or `Invalid(errors)`, reporting every error at once (required fields included), one code per field. Past the parse, code only handles valid types: no `!!`, no exception, no Arrow. The application layer returns a sealed result.
- Field identifiers of errors are domain data: only the web mapper turns them into JSON paths.
- Strict JSON (`application.yml` + `shared/JacksonConfig`): no float-as-int, no scalar coercion (`123` is not a string, `"123"` is not a number), no trailing tokens, no stack trace in error bodies. No custom Jackson deserializer.

## API contract (ADR 0004)

- `back/openapi/template-api.json` is the published contract, generated by springdoc and checked by `OpenApiContractTest`. Enum values (`@field:Schema(implementation = <DomainEnum>::class)`) and `ErrorCode` come from the domain, never from hand-written lists. Every `/api/**` endpoint is published; a protected controller carries `@SecurityRequirement(name = BEARER_AUTH)` (`shared/OpenApiConfig`).
- Any change to a DTO, an enum or an error code: refresh it with `./mvnw test -Dtest=OpenApiContractTest -Dcontract.update=true`, commit the file, then run `pnpm api:generate` in `front/`.

## Naming

- Domain concepts in the project's business language, everything else in English (`getX`, `parseX`, `XRepository`, `XNormalizer`).
- Methods say what they do: `getItem`, not `read`. No `utils/` package.

## Adding a bounded context

1. Create `com.template.<name>` with `domain/<aggregate>/{model,logic,port}`, `application/<Name>Service.kt` and `adapters/{web,persistence}` (`Exposed<Name>Repository : <Name>Repository`).
2. Add a Flyway migration `V<n>__<name>.sql` if the schema changes.
3. Talk to another module only through its base package (public API) or application events.
4. Tests: pure unit tests for `logic/`, one API test (Testcontainers, `shared/PostgresTestConfig`), then `ModularityTest` and `HexagonalArchitectureTest`; refresh the API contract.

## Database

- PostgreSQL + Flyway; migrations are versioned (`V1__initial_schema.sql`, `V2__...`) and applied on startup.
- Exposed (DSL or DAO) for type-safe queries, inside `adapters/persistence` only.
- Tests run against a real PostgreSQL through Testcontainers (Docker required).

## Configuration

- Everything sensitive or environment-specific comes from env vars (`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `KEYCLOAK_*`, `SSO_*`).
- See `back/.env.template` for the full list.
